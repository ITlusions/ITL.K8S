# Cluster deployment: Talos, Cilium, MetalLB (BGP)

Deploys the ITL cluster from scratch. The main stack is **Talos** (OS), **Cilium** (CNI), **MetalLB with BGP** (LoadBalancer IPs on VLAN 99), **Traefik** (ingress), **cert-manager** (certificates), **Keycloak** at `sts.itlusions.com` (identity), and the **ITL website**.

Nodes and addresses: see [1.1-architecture.md](1.1-architecture.md).

| Node | Address | Role |
|---|---|---|
| talos-cp01 | 10.99.100.11 | control plane |
| talos-cp02 | 10.99.100.12 | control plane |
| talos-w01 | 10.99.100.21 | worker |
| talos-w02 | 10.99.100.22 | worker |
| talos-w03 | 10.99.100.23 | worker |
| control-plane VIP | 10.99.100.10 | Kubernetes API |

## Before you start

Work through this checklist. The script can't check these for you.

- [ ] Static addresses or DHCP reservations for all five nodes and the VIP, on the router.
- [ ] VLAN 100 widened on the EdgeRouters, so `10.99.100.0/24` covers the nodes and VIP. Today it's `10.99.100.0/29`, which is full. VLAN 99 (`10.99.99.0/24`) stays as the load-balancer pool.
- [ ] Router BGP settings: its ASN, and the address the nodes peer with. These go in `deploy.env`.
- [ ] A Talos factory image with the `iscsi-tools` and `util-linux-tools` extensions (https://factory.talos.dev). Copy its installer URL for `TALOS_INSTALLER_IMAGE`.
- [ ] The install disk on each node is identified. It must not be the Longhorn data disk.
- [ ] A workstation with `talosctl`, `kubectl`, `helm`, and `envsubst`.
- [ ] The latest stable Talos release is confirmed for `TALOS_VERSION`.

## Step 1: boot the nodes into Talos (manual)

This step can't be scripted from the workstation. Each node needs the Talos image booted, either from a USB stick or ISO, or over PXE.

1. Boot each node from the factory ISO or USB stick.
2. Confirm the node is in maintenance mode, with `talosctl --nodes <ip> --insecure version`.
3. Check the network interface name with `talosctl --nodes <ip> --insecure get links`. Put it in `NODE_INTERFACE`.

The script installs Talos to disk and applies the configuration.

## Step 2: fill in the environment file

```
cd scripts/cluster
cp deploy.env.example deploy.env
```

Set at least:
- `TALOS_INSTALLER_IMAGE`: the factory installer URL.
- `NODE_INTERFACE` and `INSTALL_DISK`.
- `NODE_GATEWAY`: the default gateway for the node subnet.
- `BGP_ROUTER_ASN` and `BGP_ROUTER_ADDRESS`.

`deploy.env` is git-ignored, and so is `generated/`, which holds the cluster secrets and kubeconfig.

## Step 3: run the deployment

```
scripts/cluster/deploy-talos.sh
```

The script:
1. generates the Talos secrets once, and the machine configs (`scripts/cluster/generated/`),
2. applies the config to every node, with the hostname and static address for each,
3. bootstraps etcd on the first control-plane node, and writes `generated/kubeconfig`,
4. waits for the API, then installs Cilium as the CNI,
5. installs MetalLB, and applies the VLAN 99 pool, the BGP peer, and the advertisement from `manifests/metallb/`,
6. waits for all nodes to be Ready, and prints them.

It's safe to re-run. Existing secrets are reused, bootstrap is skipped if etcd already exists, and applies are idempotent.

## Step 4: verify

```
export KUBECONFIG=scripts/cluster/generated/kubeconfig
kubectl get nodes -o wide                 # all five Ready
kubectl -n kube-system get pods -l k8s-app=cilium
kubectl -n metallb-system get ipaddresspools,bgppeers,bgpadvertisements
kubectl get --raw=/readyz?verbose | tail -3
```

Check the BGP session on the router. It should show two sessions from the control-plane and worker addresses.

Test a LoadBalancer: create a Service of type `LoadBalancer`, and check it gets an address from `10.99.99.20–100`. From the LAN, the address should answer.

## Step 5: phase 2 (not automated yet)

Install these in order, from git:

1. **external-dns** (internal zone). Create the TSIG Secret, then install with `manifests/external-dns/values-internal.yaml`. It writes the `k8s.int.itlusions.nl` records from Services, Ingresses, and Gateway routes.
2. **cert-manager**. Create the `letsencrypt-issuer` ClusterIssuer for public names (HTTP-01). For the wildcard `*.k8s.itlusions.nl`, create a DNS-01 ClusterIssuer that uses the TransIP webhook on the `itlusions.nl` zone. See [1.6 DNS](1.6-dns.md).
3. **Traefik**, in two instances:
   - the public instance on the public IP (`10.99.99.27`), for the ITL website and Keycloak,
   - the internal instance (`traefik-internal`, Gateway API) on VLAN 99 (`10.99.99.26`), for internal tools. Its values are in `ITL.Traefik/itl.traefik/values-internal.yaml`.
4. **Keycloak** at `sts.itlusions.com` (realm `itlusions`).
5. **ITL website**.

Not in the main stack, so they're left out of this procedure. Confirm before installing them: **Longhorn** (storage for the Prefect database), **Argo CD**, and **Prefect**.

## Backups

Take an etcd snapshot straight after bootstrap, and then regularly. This is the backup that matters, so it comes before anything else is installed.

```
talosctl --nodes 10.99.100.11 etcd snapshot scripts/cluster/generated/etcd-$(date +%F).db
```

Store snapshots off the cluster. Keep `generated/` in a password manager or a secret store, since it holds the cluster's root of trust.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| `apply-config` fails with a TLS or certificate error | The node is already configured. Re-run; the script switches to `--mode auto`. |
| etcd doesn't start, or bootstrap fails | Check `talosctl --nodes <cp> service etcd` and the disk. Check the install disk is right. |
| Nodes stay NotReady | Cilium isn't running yet. Check `kubectl -n kube-system get pods -l k8s-app=cilium`. |
| No LoadBalancer IP assigned | Check `kubectl -n metallb-system logs deploy/metallb-controller`. The pool name must match `vlan99`. |
| BGP session down | Check the router ASN and address in `deploy.env`, and that the nodes can reach `BGP_ROUTER_ADDRESS`. |
