# 1.3 Cluster capability matrix

Hardware and capability snapshot of the live Talos cluster, confirmed via `kubectl get nodes -o json` and `kubectl describe nodes` against the running cluster on 2026-10-23. Supersedes [0.1 Cluster capabilities (Ubuntu)](../0-historical/0.1-cluster-capabilities-ubuntu.md), which is kept only as a historical record of the pre-rebuild cluster.

| itl-w01 | Worker | 12 / 11.95 | 15722644Ki / 15227028Ki |

`itl-w01`–`itl-w03` are the higher-spec compute nodes (12 cores, ~15Gi); `itl-cp01`, `itl-cp02`, and `itl-w04` are the smaller nodes (4 cores, ~8Gi). Every node is `amd64`, running `Talos (v1.14.4)`, kernel `6.18.57-talos`, `containerd://2.3.7`.

## GPU: driver present, not yet schedulable

Every node carries these Talos extension labels:

```
extensions.talos.dev/amd-ucode: 20260916
extensions.talos.dev/amdgpu: 20260916-v1.14.4
```

This means the `amdgpu` kernel driver (from the factory schematic `8479232c...` - see [1.1 Architecture](1.1-architecture.md)) is loaded on **every** node, not just the ones with a physical AMD GPU. Confirmed against the live cluster: `amd.com/gpu` does **not** appear in any node's `status.capacity` or `status.allocatable` - because no AMD GPU device plugin or Node Feature Discovery is deployed. The driver being present is necessary but not sufficient for GPU scheduling.

**What this means in practice:** a pod requesting `amd.com/gpu: 1` today would stay `Pending` forever - there's no extended resource for the scheduler to allocate, regardless of which node it lands on. [5.1–5.4 (GPU docs)](../5-gpu/5.1-gpu-overview.md) describe deploying the device plugin and NFD, but those docs predate the Talos rebuild and are written for an `apt`/`systemctl`-managed Ubuntu host - they need a Talos-specific rewrite before they're trustworthy again (flagged in the doc review; not yet done).

The pre-rebuild hardware matrix ([0.1](../0-historical/0.1-cluster-capabilities-ubuntu.md)) recorded AMD Radeon (gfx90c) GPUs on the old `itl01`/`itl02` nodes. Whether that same physical hardware is now one of `itl-w01`–`itl-w04` hasn't been re-confirmed post-rebuild - do that (`rocminfo` or `lspci` on the node, which on Talos means via a privileged debug pod, not SSH) before relying on GPU workloads scheduling to a specific node.
